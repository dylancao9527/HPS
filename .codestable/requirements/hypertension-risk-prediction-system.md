# 提供高血压 7 天风险预测能力

## 用户故事

- 作为普通用户，我希望记录血压和维护风险因素档案后，能看到未来 7 天血压趋势和高血压风险概率，而不是只能看到孤立的历史记录。
- 作为普通用户，我希望预测结果用风险等级、趋势和健康建议表达，而不是被要求理解输入快照、模型融合和置信度细节。
- 作为管理员，我希望能查看历史预测记录、置信度、异常信号和导出数据，而不是只能看到普通用户端的摘要。
- 作为论文写作者，我希望系统能力围绕 Prophet 与 LightGBM 的双模型预测链路展开，而不是写成传统 CRUD 管理系统。

## 为什么需要

血压记录本身只能说明过去发生了什么，普通用户更需要一个能解释短期趋势和风险水平的健康管理辅助能力。系统还需要把模型运行、预测可信度和历史记录保留下来，支撑管理员治理、训练数据准备和论文实验说明。

## 怎么解决

系统让普通用户维护风险因素档案并持续录入血压记录，在满足预测前校验后生成固定 7 天预测结果。普通用户只看到风险等级、高血压风险概率、未来 7 天血压趋势和指南型健康建议；更专业的输入快照、融合信息、置信度和异常信号进入管理员预测结果治理。

## 边界

- 系统不输出临床诊断结论，不替代医生诊疗或医疗决策。
- 普通用户入口不提供 3 天、14 天或其他多周期预测选择。
- 可缺失风险因素为空时，不等同于风险因素档案未完成；数据质量信号留给预测结果治理。
- 风险因素档案或血压记录未满足预测前校验时，不创建预测记录。
- 训练数据导出不自动触发模型训练，模型训练仍由本地脚本流程完成。
