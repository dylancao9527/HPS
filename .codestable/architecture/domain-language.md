# 领域语言与论文口径

本文件把旧 `CONTEXT.md` 中的领域语言、论文表达边界和命名禁区迁入 CodeStable 架构知识入口。`CONTEXT.md` 原文件已删除；CodeStable 子技能需要领域口径时读本文件。

## 1. 项目定位

- 正式论文题目固定为“基于Prophet与LightGBM的高血压风险预测系统设计与实现”。
- 系统定位是面向普通用户的高血压风险预测系统，辅助用户理解血压趋势和高血压风险，不替代临床诊断。
- 论文主线围绕 Prophet 与 LightGBM 构成的双模型预测链路展开，用户注册、权限、数据库、前端页面和后台管理都是预测链路落地的工程支撑。
- 最终论文采用模型类样文的六章节奏：绪论、相关理论、实验数据集与评价指标、双模型预测原理与系统设计、模型训练/实验结果/系统测试、总结与展望。

## 2. 核心术语

| 术语 | 项目内含义 | 避免写法 |
|---|---|---|
| 高血压风险预测系统 | 普通用户记录血压、预测高血压风险并获得健康管理建议的系统 | 临床诊断系统、医疗决策系统 |
| 双模型预测引擎 | Prophet 预测未来 7 天血压趋势，再将预测血压与风险因素输入 LightGBM 评估风险概率 | 单模型预测、模型投票 |
| 7天风险预测 | 普通用户预测入口固定输出未来 7 天血压趋势和高血压发病风险概率 | 3 天预测、14 天预测、多周期预测 |
| 血压趋势预测 | Prophet 基于历史血压记录生成未来 7 天收缩压和舒张压走势 | 风险预测、诊断结论 |
| 高血压发病风险概率 | LightGBM 基于预测血压和用户风险因素输出的未来 7 天风险概率 | 确诊概率、患病诊断 |
| 高血压风险概率 | 系统界面和工程说明中对高血压发病风险概率的稳妥简称 | 临床发病率 |
| 预测期血压特征 | Prophet 预测期结果转换得到的 LightGBM 输入特征，当前取未来 7 天收缩压和舒张压均值 | 原始 Prophet 模型、完整预测曲线 |
| 用户端预测摘要 | 普通用户看到的风险等级、风险概率、未来 7 天血压趋势和健康建议 | 模型审计、输入快照、融合元数据 |
| 风险等级 | 高血压发病风险概率映射出的低/中/高展示层级 | 病情分级、临床分级 |
| 指南型健康建议 | 基于风险信号和中国高血压防治指南（2024年修订版）知识库规则生成的健康建议 | AI 医生建议、处方、医嘱 |

## 3. 角色与数据边界

- **普通用户**：记录血压、维护个人档案、发起 7 天风险预测、查看历史结果和指南型健康建议。不要写成“患者”或“病人”。
- **管理员**：维护用户、查看系统统计、导出训练数据、执行预测结果治理。不要写成“医生”“专家”或“审核员”。
- **账户信息**：用户名、邮箱、密码摘要和角色等登录与权限数据，不是模型特征。
- **个人档案**：普通用户健康相关资料总称，包含风险因素档案与诊断反馈，不包含账户信息。
- **风险因素档案**：进入 7 天风险预测输入的个人健康与生活方式风险因素集合。
- **诊断反馈**：用户自报或反馈性健康状态信息，可以用于档案展示或训练数据导出标签来源，但不作为 LightGBM 核心风险输入。
- 管理员只拥有账户信息，不拥有个人档案、风险因素档案、诊断反馈、血压记录或预测记录。

## 4. 预测链路边界

- 血压记录按自然日聚合为每日血压序列，再进入 Prophet 血压趋势预测。
- 普通用户预测入口固定为 7 天风险预测，不向用户提供预测周期选择。
- 风险因素档案的预测前最低完整性要求为年龄、性别、身高和体重。
- 当前是否吸烟、日吸烟支数、是否服用降压药、是否糖尿病、总胆固醇和血糖可以缺失；非吸烟者的日吸烟支数按 0 处理。
- 可缺失风险因素为空时，不等同于风险因素档案未完成；系统可以继续预测，并在预测结果治理中作为模型输入字段缺失的数据质量信号呈现。
- 风险因素档案或血压记录未满足预测前校验时，不创建预测记录，也不进入预测历史或预测结果治理。
- 模型训练不自动触发训练数据导出；本地流程保持“先导出、再训练”的两步命令。
- `datasets/training_data_export.csv` 是本地数据库导出的可再生成样本文件，不进入版本控制；文件不存在时训练不阻止，只使用基础训练集。

## 5. 治理语言

- **预测结果治理**：管理员查看、追踪、导出和审查历史预测结果及其输入、趋势、风险、建议、置信度等明细，不修改模型结论。
- **模型治理能力**：围绕模型运行状态、预测可信度、异常预测和模型资产状态进行查看、追踪和解释的系统级管理能力。
- **预测链路治理**：模型治理能力的一期范围，聚焦 Prophet 模型状态、LightGBM 风险输出、预测异常和数据质量。
- **治理核心指标**：总预测次数、Prophet 复用/重训次数、低置信度预测占比、高风险预测数量、异常预测数量和数据不足预测数量。
- **异常预测**：管理员优先查看的治理信号，不代表模型已经出错，也不会自动修改预测记录。
- **治理操作边界**：一期只允许查看、筛选和导出；治理备注作为二期扩展，不覆盖原始预测结果。
- **预测记录**：系统一次预测产生的不可变历史记录，包含输入快照、趋势预测、风险结果、指南型健康建议和元信息。

## 6. 论文表达边界

- 论文不能写成普通信息管理系统，也不能为了贴近深度学习样文而夸大模型训练复杂度。
- 第 4 章应先解释 Prophet、LightGBM、预测期血压特征、风险概率、健康建议和预测记录治理之间的关系，再展示系统页面落地。
- 数据库设计应收束为服务双模型预测引擎和 7 天风险预测的数据结构设计，不独立扩写成论文主线。
- 正文尽量不用真实源码堆叙，优先使用流程图、公式、接口表、数据结构表、页面截图和核心逻辑摘要。
- 页面截图应服务预测链路，优先覆盖风险因素档案、血压记录、风险预测页、预测结果页、预测历史页和预测结果治理页。
- 参考文献应重新建池并核验，优先覆盖高血压风险预测、Prophet/时间序列预测、LightGBM/机器学习分类、健康管理系统和中国高血压防治指南。
- 中国高血压防治指南统一写“2024年修订版”，不要回退到 2023 表述。
- 盐摄入量、睡眠时长等字段只作为后续扩展风险因素，不写成当前已实现模型输入。
