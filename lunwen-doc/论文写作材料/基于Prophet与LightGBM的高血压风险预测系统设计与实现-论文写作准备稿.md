| 主题 | 任务书/开题报告口径 | 当前实现事实 | 论文最终采用口径 |
|---|---|---|---|
| 论文题目 | 基于 Prophet 与 LightGBM 的高血压风险预测系统 | 一致 | 《基于Prophet与LightGBM的高血压风险预测系统设计与实现》 |
| 系统定位 | 高血压风险预测与健康建议 | 面向普通用户的健康管理辅助系统 | 风险预测辅助系统，不写成临床诊断系统 |
| 核心模型 | Prophet + LightGBM | Prophet 预测未来 7 天血压趋势，LightGBM 输出风险概率 | 双模型串联预测链路 |
| 预测周期 | 未来 7 天 | 后端约束固定 7 天 | 统一写“7天风险预测” |
| Prophet 输入 | 用户血压记录 | 按自然日聚合为每日血压序列，最多使用近期 90 天 | 历史血压记录经日均聚合形成趋势预测输入 |
| LightGBM 输入 | 预测血压和用户行为因素 | 风险因素档案 + Prophet 预测期血压特征 | 预测期血压特征取未来 7 天预测收缩压、舒张压均值 |
| 风险因素 | 曾提到盐摄入量、睡眠时长等 | 当前核心字段为年龄、性别、BMI、吸烟、降压药、糖尿病、胆固醇、心率、血糖等 | 不把盐摄入量、睡眠时长写成已实现模型输入，只放展望 |
| 诊断反馈 | 可作为用户健康状态 | 不进入用户侧 LightGBM 核心风险输入 | 可作为训练数据导出标签来源或扩展信息，避免标签泄漏 |
| 指南依据 | 开题/任务中有 2023 口径 | 项目知识库采用《中国高血压防治指南（2024年修订版）》 | 正文统一写 2024 年修订版 |
| 实验数据 | 未细化 | Framingham Heart Study（`framingham.csv`），4240 条样本 | 第3章说明数据集、缺失值和划分，第5章呈现实验指标 |
| LightGBM 结果 | 未细化 | Tuned：Accuracy 0.8797、AUC 0.9480、Precision 0.8286、Recall 0.7719、F1 0.7992、PR-AUC 0.8678、Brier 0.0829、Threshold 0.77 | 第5章作为核心实验结果 |
| 特征重要性 | 未细化 | sysBP 70.8%、diaBP 18.5%，血压特征总 gain 89.4% | 用于证明血压预测特征对风险分类贡献最大 |
| 系统角色 | 用户/后台 | 普通用户、管理员 | 避免写“患者/医生/诊断/医嘱” |
| 预测记录 | 未细化 | 每次预测生成不可变记录，治理只查看、筛选、导出 | 第4章写数据结构，第5章写系统测试 |

## 8. 第5章实验数据与结果使用计划

| 内容 | 可用数据 |
|---|---|
| 数据集规模 | 4240 条样本，正样本 1317，负样本 2923，正样本比例 31.1% |
| 数据划分 | 训练集 3392，测试集 848，阈值验证集 340，early-stop 验证集 306 |
| 缺失值策略 | LightGBM native 缺失值处理 |
| Baseline 指标 | Accuracy 0.8738，AUC 0.9464，F1 0.7830 |
| Tuned 指标 | Accuracy 0.8797，AUC 0.9480，Precision 0.8286，Recall 0.7719，F1 0.7992，PR-AUC 0.8678，Brier 0.0829 |
| 阈值策略 | Tuned threshold 0.77，recall priority，Recall 下限 0.75 |
| 阈值策略对照实验 | 对比 `recall_priority` 与单纯最大化 `f1`：实验组（f1）Recall 达 0.8897，F1 达 0.8494，但阈值降至 0.6676；对照组（recall_priority）通过适当压低 Recall 维持高 Precision（0.8286） |
| 混淆矩阵 | TN 543，FP 42，FN 60，TP 203 |
| 特征重要性 | sysBP 70.8%，diaBP 18.5%，BMI 3.4%，age 2.2%；血压特征合计 89.4% |
| Prophet 策略 | 用户发起预测时实时训练/复用，最多使用近期 90 天日均血压数据，返回训练上下文和置信度说明 |
