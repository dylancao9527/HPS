# PRD: 精简预测存储并重设计系统界面

## Problem Statement

高血压风险预测系统当前把一次 7 天风险预测拆成多张预测和 Prophet 明细表。普通用户只需要看到用户端预测摘要，管理员一期也只需要围绕预测链路治理查看风险、置信度、异常和追溯明细；过细的表结构让数据库显得杂乱，接口和前端也被迫理解太多存储细节。同时现有界面偏卡片化和装饰化，需要调整为更清晰、专业、适合健康管理系统反复使用的布局风格。

## Solution

将预测历史存储收束为一个紧凑的预测记录聚合。`prediction_records` 保存必要筛选列和 JSON 载荷，删除一次预测历史相关的 Prophet/预测明细表。后端继续向普通用户和管理员返回稳定的预测、历史、治理接口；前端隐藏存储细节，重新组织导航、页面框架、卡片密度、表格和治理页面视觉层级。

## User Stories

1. As a 普通用户, I want 预测页只展示 7 天风险预测摘要, so that 我能快速理解风险概率、趋势和建议。
2. As a 普通用户, I want 历史页继续查看每次预测的趋势和建议, so that 数据库存储简化后我的使用体验不倒退。
3. As an 管理员, I want 预测结果治理继续按风险等级、置信度和异常状态筛选, so that 我能优先查看需要关注的预测记录。
4. As an 管理员, I want 预测明细仍能展示输入快照、融合信息、趋势摘要、置信度原因和指南型健康建议, so that 数据库表减少后追溯能力仍然存在。
5. As a 维护者, I want 一次预测历史由单一预测记录模块负责, so that 后续调整预测结果结构时不需要同步维护多张浅表。
6. As a 维护者, I want Prophet 模型资产和预测历史记录分开, so that 模型复用策略不被一次预测明细表牵连。
7. As a 维护者, I want 前端布局更安静、可扫描、少装饰, so that 系统更像健康管理工具而不是营销页。

## Implementation Decisions

- 预测历史收束到 `prediction_records` 聚合表。
- 风险概率、风险等级、数据天数、置信度、运行模式和异常状态保留为普通列，满足列表、筛选、摘要和治理核心指标。
- 血压趋势预测、输入快照、风险融合元信息、Prophet 训练说明、置信度原因和指南型健康建议保存为 JSON 载荷。
- 删除一次预测历史专用的 Prophet 预测主表和六张预测明细表。
- `user_prophet_models` 保留为 Prophet 模型资产持久化表。
- 原 `/api/prophet-predictions` 兼容为从预测记录中读取趋势历史，避免前端立即承担路由迁移成本。
- 前端采用更克制的健康 SaaS 工作台风格：高对比、浅底、低圆角、清晰焦点态、密集但有层次的信息布局。

## Testing Decisions

- 后端测试覆盖预测记录 mapper、预测执行保存、历史列表、Prophet 趋势历史兼容路由、治理摘要、治理筛选和导出。
- 前端测试覆盖预测页、历史明细、管理员治理详情和预测接口契约。
- 测试只验证外部行为和接口契约，不绑定内部 JSON 存储细节之外的实现步骤。

## Out of Scope

- 不改变 7 天风险预测的业务周期。
- 不替换 Prophet 或 LightGBM 模型链路。
- 不新增在线训练或模型发布能力。
- 不把诊断反馈纳入用户侧预测输入。

## Further Notes

此 PRD 遵守“高血压风险预测系统”定位：系统提供健康管理辅助、风险概率和指南型健康建议，不输出临床诊断结论。
