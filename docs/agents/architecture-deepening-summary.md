# HPS 架构深化交付总结

## 范围

本次交付覆盖 GitHub Issues #2 到 #8，目标是在不修改数据库结构、迁移脚本和生产配置的前提下，收敛高血压风险预测系统的领域语言、预测链路和持久化边界。

## 主要成果

- 建立架构深化基线与保护网，记录后端测试、前端类型检查、lint、测试状态和领域词保护清单。
- 收敛前端风险展示语言，集中处理风险等级、高血压风险概率、置信度和血压趋势预测展示，移除“临床风险等级”等越界表述。
- 收敛 prediction freshness 策略：系统可以复用 Prophet 模型，但每次预测都会生成新的预测记录，不再 replay 旧预测结果。
- 深化指南型健康建议安全边界：建议生成入口改为显式 `guideline_signal`，并在建议引擎中集中处理 topic 分组、优先级、置信度提示和安全文案改写。
- 深化预测记录读写映射：新增 normalized rows DTO，让 repository 只负责持久化，mapper 负责规范化明细行构造和旧格式读取兼容。
- 深化 Prophet 模型生命周期：拆分训练上下文、生命周期策略和模型生命周期编排，调用方只请求 `predict(user_id, forecast_days)`。
- 深化双模型预测引擎 run module：新增 `PredictionRun`，把用户风险因素快照、预测期血压特征、风险融合、指南型健康建议和保存 payload 组装集中到一次 prediction run。

## 领域边界

- 保留领域词：高血压发病风险概率、风险等级、预测记录、血压趋势预测、指南型健康建议。
- 预测结果不表达临床诊断结论，不输出确诊、处方或药物调整指令。
- `UserProfile.diagnosis` 仍作为训练数据导出的诊断反馈语义保留，不进入本次预测结果展示语义。

## 验证记录

- 后端完整测试在 #8 收尾时通过：`uv run pytest`，98 passed。
- 前端在 #3 收尾时通过：`pnpm run typecheck`、`pnpm run lint`、`pnpm run test`。
- 涉及前端展示的关键路径已通过浏览器验证：预测页、历史页、管理员预测治理页。

## 后续建议

- 若要继续深化，可优先补充路由层到应用层的端到端测试，让预测 API 对 `PredictionRun` 的契约有更高层保护。
- 在提交后关闭 #2 到 #8，并在后续 PR 或论文材料中引用本总结作为架构演进说明。
